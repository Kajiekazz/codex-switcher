# 使用指南

[返回主 README](../README.md) · [配置与数据](reference.md) · [故障排查](troubleshooting.md)

本文介绍首次配置和日常操作。所有命令均在仓库根目录执行，默认服务地址为 `http://127.0.0.1:8787`。

## 环境与启动

| 组件 | 要求 |
|---|---|
| Windows | Windows 10/11；凭据加密和桌面集成依赖 Windows |
| Python | 3.10+；基础服务仅依赖标准库 |
| Codex CLI | 登录助手和任务续跑需要可用的 `codex` 可执行文件，可通过 `CODEX_SWITCHER_CODEX_EXE` 指定路径 |
| Chrome / Playwright | Chrome 侧边栏需要 Chrome；自动填写登录信息还需安装 Python Playwright 包 |

首次启动，启用登录助手与手动切换：

```powershell
.\start.ps1 -EnableLogin -EnableSwitch
```

若 PowerShell 执行策略阻止脚本运行，可使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -EnableLogin -EnableSwitch
```

打开[本地控制台](http://127.0.0.1:8787/)。切换启动参数前，先用 `.\stop.ps1` 停止默认端口上的服务，再执行新的启动命令。

设置面板保存的值优先于启动参数设置的环境变量。需要恢复环境变量行为时，在面板中清除对应项；标注「需重启」的设置须重启服务。完整规则见[配置参考](reference.md)。

## 账号导入与登录

### 导入账号

在账号池粘贴账号列表，每行一个账号：

```text
account@example.com|example-password|JBSWY3DPEHPK3PXP
second@example.com|example-password
third@example.com-----example-password---JBSWY3DPEHPK3PXP
```

- 推荐使用 `邮箱|密码|2FA` 格式；无 2FA 时省略第三段。
- 空行及以 `#` 开头的行会被忽略；同邮箱重复导入会更新账号信息。
- 短横线分隔格式从右侧识别 TOTP 种子，密码可能与分隔符或种子混淆时使用 `|`。
- 自动填写验证码支持 TOTP；邮箱验证码和其他验证步骤可能需要人工完成。

导入仅保存账号信息。用于切换的 `auth.json` 快照在登录授权成功后生成。

账号行可编辑标签、备注、优先级和停用状态。停用账号不会参与自动切换；拖拽排序调整优先级，仅在候选账号剩余额度相同时影响最终选择。

### 手动设备码登录

1. 使用 `-EnableLogin` 启动服务，点击账号行的「登录」。
2. 按弹窗提供的授权地址和设备码，在浏览器中完成授权。
3. 等待账号行显示登录成功，再查看快照与额度状态。

启动脚本默认使用 `manual` 驱动，无需 Playwright。每次登录在独立的 `CODEX_HOME` 中运行，成功后将凭据保存为加密快照，不替换当前账号的 `~/.codex/auth.json`。

### Playwright 登录

安装系统 Chrome 和 Python Playwright 包后，启用自动填写：

```powershell
python -m pip install playwright
.\start.ps1 -EnableLogin -EnableSwitch -Driver playwright
```

驱动使用系统 Chrome，无需执行 `playwright install`。它会填写邮箱、密码、TOTP 和设备码；需要人工验证时，按浏览器提示处理并保持自动化窗口可见。

Playwright 模式默认在导入后为缺少有效快照的账号排队登录。登录并发数默认 2，可在设置面板调整；手动模式默认通过账号行按钮逐一启动。

### 短信验证

需要自动处理手机短信验证时，在设置面板的「接码」分组选择 `grizzly`、`smsbower`、`l` 或 `h`，填写对应地址和凭据，并配置服务码、国家 ID 和价格上限。

接码卡片提供余额查询、取号测试和号码释放。取号会占用平台额度，释放结果以平台响应为准；验证方式变为 WhatsApp 时，驱动会结束当前短信尝试并请求释放号码。各项参数见[接码配置](reference.md#接码)。

## 查看额度

控制台的额度卡片显示当前账号的 5 小时、7 天窗口用量和重置时间；账号池同时提供其他账号的额度状态。历史曲线展示最近 6 小时采样，并按近期消耗速度估算耗尽时间。

预测结果依赖已有采样，样本不足时可能不显示。凭据失效或额度接口不可用时，先处理探测错误，再判断账号是否可用；详见[额度与切换排障](troubleshooting.md)。

## 切换账号

### 手动切换

1. 确认目标账号已保存登录快照。
2. 在切换卡片选择账号，勾选确认后执行切换。
3. 保持「切换后重启 ChatGPT 桌面端」勾选，或切换后点击「立即重启桌面端」。

切换更新本机 `~/.codex/auth.json`。服务会先保存当前账号快照和加密备份，再执行原子替换与校验，失败时尝试回滚并报告结果。桌面客户端在启动时读取凭据，因此切换成功后需要重启。

内置重启仅处理桌面客户端的 `ChatGPT` 进程树，独立终端中的 Codex CLI 会话不在此范围内。

### 自动切换

使用以下命令启用登录、自动切换及切换后的桌面重启：

```powershell
.\start.ps1 -EnableLogin -EnableSwitch -EnableAutoSwitch -RestartDesktop
```

默认每 90 秒检查当前账号额度，只有额度接口报告 `limit_reached=true` 或 `allowed=false` 时触发切换。候选账号须有快照、未停用、不在冷却期且额度探测成功。

候选按剩余 5 小时额度、剩余 7 天额度、账号优先级、快照保存时间依次排序。无可用候选时等待后重试，不会选择额度状态未知的账号。

冷却时间、每小时切换上限及连续失败熔断可在设置面板调整。预测耗尽前提前切换是单独的可选设置，默认关闭。参数与默认值见[自动切换配置](reference.md#自动切换)。

## 任务续跑

### 手动续跑

启用续跑功能：

```powershell
.\start.ps1 -EnableLogin -EnableSwitch -EnableGoalResume
```

1. 确认当前账号有可用额度；需要换账号时先完成切换。
2. 在会话卡片选择目标，点击「预览」检查状态。预览仅读取目标状态，不启动目标执行。
3. 确认后点击「续跑」——**默认只把目标置为 `active`**，然后你在 Codex 桌面端打开那个会话，它就会继续跑。

可选择的目标状态包括额度受限（`usage_limited`）、已暂停（`paused`）及没有回合正在执行的 `active`。已完成、被阻塞或预算受限的目标不在续跑范围内。每次最多选择 10 个目标，按顺序处理。

**默认不会在后台跑任何东西**：服务只做两件事——拿到写入锁、把目标置为 `active`，然后立刻释放。真正的回合由桌面端执行，所以进度、日志、停止都在 Codex 里。如果那个会话正被桌面端开着（行上有「桌面端占用」），我们连锁都拿不到，会直接提示你在应用里点继续。

想回到旧的「后台 app-server 真跑回合」行为，把 设置 →「目标续跑」→ **在后台 app-server 里执行续跑** 打开（`CODEX_SWITCHER_GOAL_RESUME_BACKGROUND=1`）。那个模式才会出现「接管桌面端」「最长运行 2 小时」「后台状态条」这套东西。

切号时如果排着自动续跑，服务同样只是替你把目标置为 `active`，不会关你的窗口；切完号重启桌面端后，你打开对应会话即可。

### 运行时怎么读状态

以下几项只在后台模式（设置里的「在后台 app-server 里执行续跑」）下才有意义；默认模式下续跑几秒钟就结束，不会出现长时间的状态条。

有任务在跑时，会话卡片顶部会出现一条状态条，依次显示：会话标题 · 线程 id（8 位）· 任务 id · 已运行时长 · 回合进行中时长 · 最后活动时间。

- **同一个标题可能对应两个线程**：从原会话 fork 出来的副本会沿用标题，而桌面端打开的通常是原线程。要对照标题后面的 8 位线程 id，才能确定跑的是哪一个。
- **「桌面端占用」标记**：这个会话的线程写入锁正在桌面端手里（桌面端正开着它）。锁是按线程的——桌面端开着 A 不影响 B；切到别的会话或关掉窗口，锁立刻释放。默认模式下带这个标记的行会跳过并提示你在应用里继续；只有开了后台模式才会去关桌面端接管。
- **最后活动**超过 15 分钟没有新事件时，状态条会变成橙色并提示「可能卡住」，此时可以停止续跑再排查。
- **置顶的会话会出现两次**：「置顶」区一次、它所属的「项目」区一次（与 Codex 一致）。项目里的那一行带「置顶」标记，勾选状态是同一个。
- 会话行在续跑期间只显示「正在续跑」，不会同时显示上一轮的「已续跑 · N 小时前」，避免把历史当成当前状态。

### 为会话创建目标

没有目标的会话可在会话卡片中选择后点击「建目标」，填写描述并确认。默认创建为 `paused`，之后可按上述流程预览并续跑；已有目标的会话会被跳过，不会覆盖原目标描述。

一次最多创建 50 个目标，描述最多 400 字。勾选「创建后立即激活」会将目标设为 `active`，使用前应确认该会话的任务和当前账号额度。

### 切换后自动续跑

```powershell
.\start.ps1 -EnableLogin -EnableSwitch -EnableAutoSwitch -RestartDesktop -EnableGoalResume
```

在会话行点击「自动」指定目标，并确认设置面板中的「切号后自动续跑已勾选目标」已开启。每次手动或自动切换成功后，服务会检查这些目标，仅续跑状态符合条件的目标。

若旧账号的续跑任务仍在运行，服务先尝试结束旧任务并释放会话写锁；无法结束时会跳过本次自动续跑，结果显示在任务状态中。

### 停止与会话占用

在任务卡片停止续跑；选择仍在队列中的目标时，会跳过这些目标，选择当前正在执行的目标时会结束本轮续跑任务。停止后目标可能仍显示 `active`，不代表回合仍在运行。

出现 `already has an active writer` 表示会话仍被其他进程占用。桌面接管设置默认开启，必要时会关闭桌面客户端、重试获取会话并在任务结束后重新启动桌面端。无法接管时按[续跑排障](troubleshooting.md)检查占用进程。

## 额度重置券

额度卡片显示当前账号的可用重置券。手动使用需要再次确认，消耗不可撤回。

自动使用默认关闭，可追加 `-EnableAutoReset`：

```powershell
.\start.ps1 -EnableSwitch -EnableAutoSwitch -RestartDesktop -EnableAutoReset
```

默认在当前账号额度受限、无可用候选且 7 天窗口已使用至少 98% 时检查可用券。若已知距自然重置不足 72 小时则跳过；重置时间未知不会单独阻止自动使用。

默认自动使用上限为滚动 7 天内 1 张，计数保存在当前服务进程中，重启后清空。具体阈值、优先用券选项及状态原因见[重置券配置](reference.md#额度重置券)。

## 侧边栏与托盘

Chrome 安装步骤、徽章含义和侧边栏截图见[浏览器扩展](../extension/README.md)。扩展连接本地服务，安装后仍需保持服务运行。

使用托盘模式后台启动服务：

```powershell
.\start.ps1 -EnableLogin -EnableSwitch -Tray
```

托盘显示当前状态，`Ctrl+Alt+C` 打开控制台。若检测到服务已运行，托盘模式复用现有服务，本次命令中的开关不会改变该服务配置。
