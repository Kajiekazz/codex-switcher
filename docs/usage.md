# 使用指南

[返回主 README](../README.md) · [配置与数据](reference.md) · [故障排查](troubleshooting.md)

本文介绍首次配置和日常操作。所有命令均在仓库根目录执行，默认服务地址为 `http://127.0.0.1:8787`。

## 安装版：首次使用与托盘

下载对应 Windows 架构的安装包后直接安装，主程序自带 Python 运行环境。双击桌面图标，系统默认浏览器打开现有管理页。首次引导检测 Codex；找不到时可重新检测或通过系统文件选择窗口指定 `codex.exe`。电脑仍需安装 Codex。

首次引导依次进行「检测环境 → 准备组件 → 添加账号 → 完成」。检测到本地 `auth.json` 中的 ChatGPT 登录账号后默认勾选，在账号步骤点击「下一步」时导入；不会改写当前凭据，也不会清空池内已有密码或 TOTP。已保存且仍有效的快照不重复导入。

添加其他账号时直接在引导中导入并查看进度，至少一个账号可用后即可完成；其余待验证账号保留。步骤和选择会保存，刷新或重启后可继续；「稍后设置」关闭自动提示，设置中的「重新打开使用引导」可再次打开。已有可用账号且没有未完成引导的用户直接进入管理页。

第一次自动登录前下载专用浏览器，页面显示下载状态、进度和失败重试。下载在生成设备授权码之前完成，之后复用已下载组件；切换到手动授权无需下载。专用浏览器与承载管理页的系统浏览器相互独立。

引导推荐配置 TOTP，可点击「一键开启并保存 TOTP」，在该账号的专用浏览器中完成绑定。程序读取绑定密钥或在本机解码二维码，生成验证码，并在确认官方页面显示已开启后加密保存。出现额外验证或自动操作失败时保留窗口，状态变为「等待手动验证」；可接管、填写已有密钥或导入绑定二维码，也可跳过。已有验证器不会自动解绑重建。「TOTP 密钥已保存」仅表示 Switcher 持有密钥；手动导入后仍需确认官方已完成绑定。

关闭网页后服务继续运行。托盘右键菜单提供「打开管理页」「开机自启」「退出 Switcher」；开机自启默认关闭，与设置中的同名开关读取同一项 Windows 配置。开启后下次登录 Windows 时只驻留托盘，后台功能沿用原设置。关闭自启只影响下次登录；退出 Switcher 关闭自身服务，Codex 已经开始执行的回合继续运行。

升级时覆盖安装即可，账号、配置和下载组件保留。日志位于 `%LOCALAPPDATA%\CodexSwitcher\logs\app.log`。安装包与自动构建见[打包说明](packaging.md)。

## 源码版：环境与启动

| 组件 | 要求 |
|---|---|
| Windows | Windows 10/11；凭据加密和桌面集成依赖 Windows |
| Python | 3.10+；基础服务仅依赖标准库 |
| Codex CLI | 登录助手和任务续跑需要可用的 `codex` 可执行文件，可通过 `CODEX_SWITCHER_CODEX_EXE` 指定路径 |
| Chrome / Playwright | Chrome 侧边栏需要 Chrome；自动填写登录信息还需安装 Python Playwright 包 |

首次启动，启用登录助手；手动切换默认可用：

```powershell
.\start.ps1 -EnableLogin
```

若 PowerShell 执行策略阻止脚本运行，可使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -EnableLogin
```

打开[本地控制台](http://127.0.0.1:8787/)。切换启动参数前，先用 `.\stop.ps1` 停止默认端口上的服务，再执行新的启动命令。

启动窗口只观察服务，关闭窗口后服务继续运行；停止服务使用 `stop.ps1`。输出和错误写入仓库根目录 `service.out.log`、`service.err.log`，退出码见 `service-launcher.log`。

设置面板保存的值优先于启动参数设置的环境变量。需要恢复环境变量行为时，在面板中清除对应项；标注「需重启」的设置须重启服务。完整规则见[配置参考](reference.md)。

## 账号导入与登录

### 导入账号

在账号池粘贴账号列表，每行一个账号：

```text
account@example.com|example-password|JBSWY3DPEHPK3PXP
second@example.com|example-password
third@example.com-----example-password---JBSWY3DPEHPK3PXP
```

- 推荐使用 `邮箱|密码|2FA` 格式；无 2FA 时省略第三段。
- 空行及以 `#` 开头的行会被忽略；同邮箱重复导入会更新账号信息。
- 短横线分隔格式从右侧识别 TOTP 种子，密码可能与分隔符或种子混淆时使用 `|`。
- 自动填写验证码支持 TOTP；邮箱验证码和其他验证步骤可能需要人工完成。

账号资料保存成功与登录成功分别显示。用于切换的凭据快照在登录授权成功后生成；登录失败时资料仍保留，无需重新导入。

账号行可编辑标签、备注、优先级和停用状态。停用账号不会参与自动切换；拖拽排序调整优先级，仅在候选账号剩余额度相同时影响最终选择。

### 手动设备码登录

1. 使用 `-EnableLogin` 启动服务，点击账号行的「登录」。
2. 按弹窗提供的授权地址和设备码，在浏览器中完成授权。
3. 等待账号行显示登录成功，再查看快照与额度状态。

启动脚本默认使用 `manual` 驱动，无需 Playwright。每次登录在独立的 `CODEX_HOME` 中运行，成功后将凭据保存为加密快照，不替换当前账号的 `~/.codex/auth.json`。

### Playwright 登录

安装系统 Chrome 和 Python Playwright 包后，启用自动填写：

```powershell
python -m pip install playwright==1.64.0 pillow==12.0.0 zxing-cpp==3.1.1
.\start.ps1 -EnableLogin -Driver playwright
```

源码版默认使用系统 Chrome；若已通过引导下载专用浏览器，则复用专用浏览器。安装版首次自动下载组件。驱动会填写邮箱、密码、TOTP 和设备码；需要人工验证时，按浏览器提示处理并保持自动化窗口可见。

Playwright 模式默认在导入后为缺少有效快照的账号排队登录。导入单个新号会打开登录进度弹窗；批量导入显示统一进度面板，可点开各账号查看步骤和失败原因。「查看登录」只查看现有任务；失败后使用「重试登录」。关闭进度弹窗不取消任务，排队中的任务也可单独取消。

新导入账号的首次自动登录依次进行；已有凭据的账号可按设置并发登录，默认上限 2。遇到邮箱验证码，或验证器要求验证码但未提供 TOTP 密钥时，可在登录进度弹窗填写本次验证码，点击「提交并继续」。错误或过期后原地重填，通过后继续设备授权；临时验证码不会作为 TOTP 密钥保存，也不会写入任务历史。

无法识别的验证页面保留原浏览器窗口，使用「前往验证窗口」手动完成。等待人工输入时允许队列继续处理其他账号，同一账号不会重复打开任务；达到窗口总数上限后，后续账号继续排队。手动驱动使用默认浏览器，不支持弹窗代填验证码。关闭进度弹窗只收起进度；取消、关闭专用验证窗口或等待超时后，账号资料仍保留。

### 短信验证

需要自动处理手机短信验证时，在设置面板的「接码」分组选择 `grizzly`、`smsbower`、`l` 或 `h`，填写对应地址和凭据，并配置服务码、国家 ID 和价格上限。

接码卡片提供余额查询、取号测试和号码释放。取号会占用平台额度，释放结果以平台响应为准；验证方式变为 WhatsApp 时，驱动会结束当前短信尝试并请求释放号码。各项参数见[接码配置](reference.md#接码)。

## 查看额度

控制台按接口实际返回的窗口时长显示用量与重置时间，账号池同时提供其他账号的额度状态。Free、Plus、Pro 共用这套数据解析，不假定所有套餐都有 5 小时和 7 天窗口。接口明确返回空窗口时显示「不适用」，缺字段或百分比异常时显示「未知」，不会按剩余 100% 参与排序。历史曲线展示最近 6 小时采样，并按近期消耗速度估算耗尽时间。

同套餐且额度窗口相同的候选比较剩余比例，跨套餐或窗口不同则按账号优先级和快照时间选择。自动续跑还会核对原会话模型：模型目录只用于预检，不代表已确认账号权限。跨套餐且未有成功执行记录时暂缓自动切号；可手动切换后通过 Switcher 续跑验证。确认执行成功或明确被拒绝的结果在凭据不变时保留 30 分钟，避免对无权限模型反复投递；不会自动更换会话模型。

预测结果依赖已有采样，样本不足时可能不显示。凭据失效或额度接口不可用时，先处理探测错误，再判断账号是否可用；详见[额度与切换排障](troubleshooting.md)。

## 切换账号

### 手动切换

1. 确认目标账号已保存登录快照。
2. 在切换卡片选择账号，勾选确认后执行切换。
3. 保持「切换后重启 ChatGPT 桌面端」勾选，或切换后点击「立即重启桌面端」。

切换更新本机 `~/.codex/auth.json`。服务会先保存当前账号快照和加密备份，再执行原子替换与校验，失败时尝试回滚并报告结果。桌面客户端在启动时读取凭据，因此切换成功后需要重启。

内置重启仅处理桌面客户端的 `ChatGPT` 进程树，独立终端中的 Codex CLI 会话不在此范围内。

### 自动切换

使用以下命令启用登录、自动切换及切换后的桌面重启：

```powershell
.\start.ps1 -EnableLogin -EnableAutoSwitch -RestartDesktop
```

默认每 90 秒检查当前账号额度，只有额度接口报告 `limit_reached=true` 或 `allowed=false` 时触发切换。候选账号须有快照、未停用、不在冷却期且额度探测成功。

候选按剩余 5 小时额度、剩余 7 天额度、账号优先级、快照保存时间依次排序。无可用候选时等待后重试，不会选择额度状态未知的账号。

所有账号耗尽后继续监控。其他账号恢复时按条件切换；若先恢复的是当前账号，则直接恢复已开启自动恢复、且明确因额度中断的会话，不需要先切到其他账号。等待恢复的账号记录在服务重启后保留；检测仍受巡检间隔和冷却时间影响。

冷却时间、每小时切换上限及连续失败熔断可在设置面板调整。预测耗尽前提前切换是单独的可选设置，默认关闭。参数与默认值见[自动切换配置](reference.md#自动切换)。

## 任务续跑

### 续跑任务

会话行提供两个明确入口：

| 模式 | 行为 |
|---|---|
| 单次续跑 | 只执行当前一轮。缺少目标时补建为暂停，已有激活或额度受限目标先暂停自动推进，再投递一条「继续」；本轮结束不再自动开启下一轮 |
| 持续续跑 | 缺少目标时补建并激活；已有暂停或额度受限目标恢复激活，由 Codex 长期目标推进到完成、暂停、受限或需要用户处理 |

两种模式都保留已有目标描述；已完成、受阻和预算受限目标不重新激活。自动目标只要求完成本会话中用户已明确要求、尚未完成的任务，不扩展范围。批量操作先选择模式，再点击「续跑所选」，一次最多 10 个会话，每个会话独立执行，允许同时运行。

补建目标失败时仍尝试发送「继续」，队列显示补建失败原因。单次模式会先确认不存在仍激活的目标；若无法暂停目标，就不投递，以免单次变成持续执行。补建成功但消息入队失败时，新目标暂停保留，重试时复用。

当前回合正在运行时不重复手动投递，提示「会话正在运行，未重复投递」，保留原运行状态；批量操作跳过运行中的会话并处理其余会话。服务请求已运行的 Codex 后台加载会话，真正执行由桌面端负责，并消耗当前账号额度。桌面端没有就绪时消息保留在队列中，看护会继续检查和重试唤醒。

### 切号后自动恢复

在会话行开启「切号自动恢复」，状态显示为「切号自动恢复：已开启」。普通会话也可使用，实际恢复时会补建缺失的长期目标；只开启此偏好不会创建目标或启动回合。队列和会话列表共用这一设置。

需要统一暂停时，关闭「设置 → 会话续跑 → 自动恢复总开关」。总开关默认开启，已保存的关闭设置仍保留；关闭只影响后续恢复，当前执行继续，各会话选择保留。

切号前服务记录真实回合状态，切号成功后只处理已开启的会话：

- 因额度耗尽而中断，且有明确额度受限记录的会话。
- 切号前正在执行，并被本次桌面端重启打断的会话。

自动恢复沿用该会话原来的单次或持续模式，服务重启后也保留；已结束的单次不会因后续切号重复启动。主动暂停、已完成、受阻、预算受限、已归档和空闲会话会跳过。单次模式为防止自动推进而暂停的目标，仍可恢复其明确因额度中断、尚未结束的这一轮。目标的 `active` 标记或线程写锁本身不能证明正在执行；状态无法确认时跳过，并保留原因。未重启桌面端时，不会为仍在执行的会话额外发送「继续」。

### 续跑队列

队列只列 Switcher 发起的手动续跑、切号自动恢复和额度恢复续跑，允许多个会话同时执行。一个会话一行，展开可查看最近 10 次请求及长期目标；同名会话用项目和短 ID 区分。

队列每行显示「单次续跑」或「持续续跑」。暂停后的会话直接显示在「已暂停」区域，点击「继续」按原模式恢复；需要改模式时使用会话行的明确入口。运行或排队期间的继续按钮不可用，避免重复投递。

| 分组 | 含义 |
|---|---|
| 等待续跑 | 等待投递、已排队、启动确认中，或等待已激活目标的下一回合 |
| 续跑中 | 已确认真实回合正在执行；长期目标的后续目标回合继续归在同一行 |
| 需处理 | 投递或执行报错、启动未确认、暂停操作未完成等 |
| 已暂停 | 保持在主列表中，可直接继续 |
| 最近结束 | 本次执行结束或已取消，默认折叠，保留最近 20 个会话 |

消息离开 Codex 队列后先核对对应回合。出队后 90 秒仍无匹配证据时显示未确认，不会自动重复发送；如果会话本身正在运行，显示「会话运行中 · 本次续跑待确认」，不将会话判为失败。「查看会话」只打开 Codex 查看进度，不重新投递。「单次续跑已结束」表示本次一轮已完成；持续模式下长期目标仍激活时，队列继续观察下一目标回合，直到目标暂停、受限或完成。用户后来手动发起的回合不会冒充这次续跑。

置顶会话可能同时出现在顶部与所属项目中，勾选状态共享。投递日志位于「任务日志」，只读预览位于「高级操作」。

### 取消、暂停与停止

勾选会话后点击「取消所选排队」；不勾选时可取消全部由 Switcher 添加且尚未执行的消息。撤回通过 Codex 队列接口进行，不修改数据库，也不删除用户自行添加的消息。投递期间取消一个会话，其他会话继续发送。

「暂停后续续跑」会撤回可撤回的 Switcher 消息、暂停长期目标，并保存该会话的暂停意图。服务重启或随后切号也会尊重暂停；只有手动继续才解除。自动恢复开关保持原选择。「暂停全部后续续跑」对当前队列中可暂停的会话应用同样规则。

消息已出队时可能无法撤回。「暂停后续续跑」保留当前回合，运行时显示「当前回合待停止」；需要同时停止当前回合，可使用「删除」或前往 Codex 手动停止。若目标暂停失败，会保留具体错误和重试入口。

「删除」会撤回 Switcher 的排队消息、暂停长期目标，并通过桌面端的会话协调通道强制中断当前回合，无需等待任务自然结束。确认撤回、暂停和中断后才移出列表；失败保留记录及原因。删除保留 Codex 原会话和投递历史，服务重启后仍保持移出状态；以后手动继续会重新显示该会话。操作按会话与当前回合 ID 定位，不关闭桌面端。

### 长期目标

在「会话详情 → 长期目标」统一管理。没有目标时填写描述（最多 400 字），可只保存，也可「保存并开始目标」；目标先保存为暂停，再按明确的开始操作激活并投递。已有目标直接复用原描述，可继续或暂停；已完成、受阻或预算受限目标不会被继续操作重新激活。

长期目标用于跨回合持续推进到完成；切号自动恢复用于衔接因切号或额度中断的任务，两者可独立使用。

旧的 `-EnableGoalResume` 参数及 `ENABLE_GOAL_RESUME` 配置保留兼容，已不作为手动继续的启用条件。更新 Python 后端后需重启 Switcher 服务；新页面会阻止向旧版本服务提交新操作。

## 额度重置券

额度卡片和账号池分别显示剩余重置券与当前适用数量。手动「用券」始终可提交，不按缓存中的库存、适用次数或自动策略阈值禁用；服务会重新查询可用券，由上游判断实际能否重置。提交前需要确认，消耗不可撤回。

自动使用默认关闭，可追加 `-EnableAutoReset`：

```powershell
.\start.ps1 -EnableAutoSwitch -RestartDesktop -EnableAutoReset
```

默认在当前账号额度受限、无可用候选且 7 天窗口已使用至少 98% 时检查可用券。若已知距自然重置不足 72 小时则跳过；重置时间未知不会单独阻止自动使用。

默认自动使用上限为滚动 7 天内 1 张，计数保存在当前服务进程中，重启后清空。具体阈值、优先用券选项及状态原因见[重置券配置](reference.md#额度重置券)。

## 侧边栏与托盘

安装版使用上述原生托盘。以下 PowerShell 托盘方式保留供源码用户使用。

Chrome 安装步骤、徽章含义和侧边栏截图见[浏览器扩展](../extension/README.md)。扩展连接本地服务，安装后仍需保持服务运行。

使用托盘模式后台启动服务：

```powershell
.\start.ps1 -EnableLogin -Tray
```

托盘显示当前状态，`Ctrl+Alt+C` 打开控制台。若检测到服务已运行，托盘模式复用现有服务，本次命令中的开关不会改变该服务配置。
