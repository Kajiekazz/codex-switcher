## 服务与配置

### 控制台无法访问，或扩展徽章显示 `!`

先检查健康检查地址是否可访问。安装版双击桌面图标；源码版在仓库根目录启动：

```powershell
pythonw switcher.pyw
```

启动器日志位于当前数据目录的 `logs/app.log`。需要查看终端错误时使用 `python service.py` 前台调试。若已有实例占用端口，从对应托盘退出，或在前台服务的原终端按 `Ctrl+C` 停止后再启动。

### 切号时 Switcher 服务消失

先查看健康检查，确认服务是否仍在运行。推荐使用安装版或 `pythonw switcher.pyw` 原生启动器，日志写入数据目录的 `logs/app.log`。前台调试服务会随其所在终端退出。

桌面端重启还会检查 Switcher 及其父进程。如果服务是从 Codex 任务内启动、关闭桌面端会连带杀死服务或启动 PowerShell，则跳过关闭并返回 `service_in_desktop_tree`。从独立 Windows Terminal 启动服务后可正常重启桌面端。

停止托盘实例使用右键菜单的「退出 Switcher」；源码版也可在相同数据目录配置下执行 `pythonw switcher.pyw --exit`。

### 页面或电脑间歇性卡顿

页面会合并同时进行的相同 GET 请求，防止慢请求在每轮刷新时重复堆积；隐藏标签页暂停自动刷新，回到前台后恢复。若整个电脑仍卡顿，用任务管理器检查实际 CPU 占用，尤其是并行测试、编译任务。服务 CPU 很低不能排除其他后台任务占满处理器。

### 返回 `423 login_disabled`

在控制台设置中启用登录助手。手动切换始终可用，不需要“允许切号”开关；自动切换在设置中单独启用。

### 修改参数或环境变量后行为未变化

设置优先级为：**设置面板保存的值 > 环境变量 > 默认值**。若需恢复环境变量配置，在设置面板清除对应项后保存。

修改终端环境变量后需退出并重新启动服务。重复打开启动器只会复用已有服务，不会更新进程环境。部分设置项保存后仍需重启，具体以面板提示为准。

## 账号与登录

### 导入成功但无法切换，或提示没有可用快照

导入仅保存账号信息。启用登录助手后，点击账号行的「登录」并完成授权，生成凭据快照。快照缺失、无效或与目标邮箱不一致时，需要重新登录。

### 提示 `codex_not_found`

登录和续跑需要可用的 Codex CLI。在运行配置中查看 `codex_exe`。服务依次检查：

1. `CODEX_SWITCHER_CODEX_EXE` 指定的文件。
2. `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe` 中最新的文件。
3. `PATH` 中的 `codex` 命令。

若自动检测失败，将 `CODEX_SWITCHER_CODEX_EXE` 设置为实际 `codex.exe` 的完整路径，再启动服务。

### 控制台显示 token 已过期，或额度探测返回 `401`

「token 已过期」表示快照中的 access token 已超过有效期。快照仍可能包含 refresh token，但是否能续期取决于账号与服务端状态。额度查询失败或凭据已撤销时，重新登录并获取快照后重试。

### 设备码授权停留在等待状态

使用当前弹窗中的设备码完成授权；设备码失效后取消此次登录并重新开始。若出现 `device_code_login_disabled`，按登录提示在账号安全设置中启用设备代码登录，再重试。

### Playwright 未安装、找不到 Chrome 或登录页面报错

安装版不要求另装 Playwright 或 Chrome。首次自动登录会下载专用浏览器；下载失败时，在设置中重新打开使用引导，点击「重试下载」，也可改用手动授权。组件状态见 `/api/setup/status`；安装版日志位于 `%LOCALAPPDATA%\CodexSwitcher\logs\app.log`。

源码版原有自动登录模式需要 Playwright 和系统安装的 Chrome：

```powershell
python -m pip install playwright
```

源码版未下载专用浏览器时使用 `channel="chrome"`；安装版或已准备专用组件时使用匹配的下载版本。保持登录窗口可见，检查页面提示；自动模式失败时可在设置中切换手动驱动，完成设备码授权。

### 多个登录窗口互相争用焦点

在设置面板将 `login_concurrency` 降至 `1` 后重试。默认并发数为 `2`，适用于自动登录；逐个手动授权时可使用单并发。

## 自动切换与桌面端

### 自动切换未触发

确认切换与自动切换两个开关均已启用。默认仅在额度接口返回 `limit_reached=true` 或 `allowed=false` 时切换；预测耗尽前切换需要额外启用预测设置。

查看自动切换状态中的最近结果，排查检查间隔、账号冷却、每小时次数上限和连续失败熔断。完整策略见[配置参考](reference.md)。

### 自动切换持续返回 `no_candidate`

检查其他账号是否已保存有效快照、是否被停用或处于冷却期，以及额度是否仍可用。探测失败的账号不会作为候选；若返回 `401`，重新登录该账号。

### 未选中手动设置的高优先级账号

同套餐且窗口相同的候选按剩余额度排序，`priority` 用于平局比较；跨套餐或窗口不同时按优先级和快照时间选择，不直接比较百分比。额度未知的账号不参与自动切号。原会话模型不在候选目录、曾被服务端拒绝，或跨套餐权限未确认时会显示跳过原因；手动切换后通过 Switcher 续跑成功可确认权限，程序不会自动降低或更换模型。

### 切换成功后桌面端仍显示旧账号

桌面端在启动时读取 `auth.json`。点击控制台中的「立即重启桌面端」，或启动时追加 `-RestartDesktop`，在后续切换成功后自动重启。

重启功能只处理桌面客户端的 `ChatGPT` 进程树，不会终止独立终端中的 Codex CLI。仅关闭桌面窗口可能仍保留后台进程。

### 导入后的首次登录失败

如果显示「等待手动验证」，本次任务仍在等待操作，不是登录失败。邮箱验证码和缺少密钥的验证器验证码可在登录弹窗填写，提交后等待验证与授权完成；输入错误或过期时原地重填。没有输入框或遇到人机验证时，点击「前往验证窗口」，在保留的浏览器窗口完成操作。其他账号可以继续处理；关闭进度弹窗不取消任务，需要停止时使用取消按钮。

TOTP 自动配置无法完成时，可在同一窗口手动设置，再填写绑定密钥或导入绑定二维码。临时 6 位验证码不能作为密钥保存。看到二维码、关闭绑定弹窗均不代表官方已启用；提交后中断时，候选密钥会加密保留，但不会标为已配置。

导入只保证账号资料已保存，登录成功后才生成可切换凭据。导入单个账号会打开登录进度，批量导入显示所有账号的状态；「查看登录」不重新发起授权，失败后点「重试登录」。登录历史包含触发来源（导入／手动）、失败步骤和尝试次数，设备码生成失败也会记录。

新号首次登录依次进行。网络和页面短暂故障最多额外重试一次；短信超时、密码错误等保留明确原因，不自动重跑整套流程。历史中曾出现首次短信超时、重试成功的案例，不能据此认定所有首次失败都属于同一原因。

## 任务续跑

### 会话操作不可用

手动继续不再需要启用目标续跑。若新页面提示后端过旧，请重启 Switcher 服务再刷新。切号自动恢复在会话行开启；若显示全局暂停，前往「设置 → 会话续跑 → 自动恢复总开关」恢复。主动暂停、已完成、空闲或未确认执行的会话会跳过。

### 队列已暂停，但当前回合仍在运行

「暂停后续续跑」会保存暂停意图、撤回可撤回消息，并暂停已有长期目标。当前回合由桌面端持有，使用该行的「前往 Codex 停止」完成停止。观察到结束记录后才移入已暂停历史；状态无法确认时显示「停止待确认」。目标暂停失败会显示原因，可重试暂停。切号不会清除暂停意图，只有手动继续会解除。

需要立即中断并移出列表时使用「删除」。它通过桌面端的协调通道定位会话 owner，按当前回合 ID 中断，不等待任务自然结束。若显示 `no-client-found`、`request-version-mismatch` 或 `desktop_stop_not_confirmed`，记录会保留；检查桌面端是否正常运行并刷新后重试。独立 app-server 的 `turn/interrupt` 不能替代这一通道。

### 显示「已排队」，但 Codex 里没有反应

服务先把「继续」写入会话队列，再通过 `codex://threads/wake/<会话>` 请求后台加载。入队、发出唤醒请求、实际执行是三个不同阶段。

1. 确认桌面端已正常启动。普通续跑的后台唤醒只加载已有应用；Windows 开机自启可先启动 Codex，切号流程可按设置重启。挂起的启动占位进程不算已启动。
2. 查看任务日志中的「已发送后台唤醒请求」。这只表示 URI 已交给系统，不证明桌面端收到、会话加载完成或回合开始。设置 `GOAL_RESUME_WAKE=0` 时不会发出请求。
3. 检查目标会话是否已有回合执行，以及是否有更早的队列消息。已有活动不能作为这次投递成功的证据。
4. 若只有手动打开会话才执行，记录入队、唤醒、打开会话和新回合开始的时间，分别检查后台唤醒与页面导航路径。

设置「等待排队消息出队（秒）」默认等待 12 秒，只控制本次观察窗口；延长等待不会修复加载或执行故障。历史测试曾观察到 2–148 秒延迟，但该区间不能作为所有任务都会自动执行的保证。

### 队列看护不断重试

看护默认每 15 秒只读检查 `~/.codex/queue_1.sqlite`，按 15/30/60/120/300/600 秒退避重发后台唤醒请求。达到 6 小时 TTL 后停止重试。持续 `pending` 只说明消息仍在队列，不能区分 URI 未到达、会话尚未就绪或队列调度未执行。

桌面端日志位于 `…\AppData\Local\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\Codex\Logs\<日期>\`。后台 `wake` 不负责页面导航，因此缺少 `ownerRoutePath=/local/<会话>` 不能证明唤醒丢失。内部 RPC 与页面 RPC 的日志级别和路由也不同；不能仅凭 INFO 日志没有 `thread/resume` 判定没有调用。

### 只有点开会话才开始续跑

旧版在 Windows 下用 `DETACHED_PROCESS` 启动 PowerShell 唤醒辅助进程。实机对照发现，这种方式可能以退出码 0 结束，却没有将协议 URI 交给 Codex；队列因而一直等到用户打开会话。现已改为 `CREATE_NO_WINDOW`：辅助进程保持隐藏，并保留正常的协议激活环境。

更新后需要重启 Switcher 服务，使其加载新的启动方式；仅刷新页面不够。已在队列中的消息无需重新添加，看护会在重试时使用修复后的唤醒方式。实机验证以未打开的置顶会话为目标，修复后约 7 秒出现 `turn_trigger="queue"` 的新回合。

静态分析、隔离对照和实机判据见[诊断记录](2026-11-02_reverse-codex-wake-report.md)。

### 消息已出队，但没有执行结果

出队仅表示队列行消失，执行、编辑或删除都可能造成这个结果。服务会继续核对投递后的新队列回合及「继续」消息：匹配成功显示「正在续跑」，并持续更新到结束、失败或中断。旧回合仍在运行不算本次投递成功。

出队后 90 秒仍未找到匹配证据时，页面显示「未找到本次续跑回合」，使用「打开会话核对」检查消息是否被编辑、删除，或记录是否暂时不可读。不要反复点击继续；程序不会自动重复添加消息。更新前已出队的最近记录会尝试回填匹配，缺少历史证据时仍保留未确认。

### 「未续跑 · 会话已归档」

会话被归档后，Codex 不会再对它执行任何消息：队列里那一行永远不会被取走。看护每 60 秒只读查一次
`~/.codex/state_5.sqlite` 的 `threads.archived`，一旦发现是已归档，就停止重发唤醒，并把结果标成
`queue_abandoned`（页面显示「未续跑 · 会话已归档」）。这**不是**投递成功，也不代表消息执行过——
队列行原样留在 Codex 的队列里，看护不会去删别人的数据。

要真的续跑：先在 Codex 里对那个会话取消归档，再重新触发一次续跑。归档期间自动续跑会直接跳过
（日志「会话已归档，跳过续跑」），不会再往队列里塞一条注定没人取的消息。

### 任务日志说「桌面端进程在，但一直没启动完成」

这时 `tasklist` 里那几条 `ChatGPT.exe` 是 Windows 创建后没有被恢复的挂起进程（单线程、约 2 MB），不会执行任何东西，也不会取走队列。服务不会把它们当成「桌面端在运行」，所以不会发唤醒深链。常见原因是 MSIX 框架包 `OpenAI.CodexPrimaryRuntime` 卡在「等待删除」：

1. `Get-AppxPackage -Name OpenAI.CodexPrimaryRuntime*` 的 `Status` 不是 `Ok`；
2. `Get-WinEvent -LogName Microsoft-Windows-AppXDeploymentServer/Operational` 能看到同一时间段的部署失败（`0x80073D3C` 等待删除，或 `0x80073D02` 程序包正在使用中）。

处理：先退出所有 Codex 相关进程，再注销并重新登录（或重启）让延迟删除完成，然后重新打开 Codex。判断是否真的起来了，看 `ChatGPT.exe` 的工作集是不是几十 MB 以上，而不是只看进程名存在。

### 提示子代理线程不能投喂

`thread/queue/add` 对未加载的 spawned sub-agent 返回 `-32600`。这类线程由父线程创建，不能直接排消息；请对父线程续跑，或取消它的「自动」标记。

### 目标显示已激活，但没有回合执行

`active` 是目标状态，不是进程运行证明。查看当前任务、逐目标结果（「成功」/「已排队」）以及 Codex 里的会话；取消后的目标也可能保留此状态。不要仅凭 `active` 判断任务仍在运行。

### 续跑没有投递成功

任务日志会写明每个目标失败的原因（线程不存在、子代理线程、`thread/queue/add` 报错等）。桌面端重启失败时任务直接失败，不会写队列。旧版本的「接管桌面端」相关设置（`GOAL_RESUME_TAKEOVER`、`GOAL_RESUME_MAX_RUNTIME` 等）已移除，设置后不再生效；看到它们出现在旧配置里可以删掉。

### 无法选择 `complete` 或 `blocked` 目标

持续续跑会恢复 `usage_limited`、`paused`、`active` 目标；单次续跑会暂停目标自动推进，只执行一轮。已完成、受阻或预算受限目标不会重新激活，但仍可接收普通续跑消息。缺少目标时先尝试补建；补建失败仍尝试发送「继续」，队列单独显示原因。单次模式无法确认目标暂停时会停止投递。写锁被占用不影响消息投递。

### 已标记目标但没有自动续跑

确认开启的是当前会话的「切号自动恢复」，核对短 ID：同名分支和已归档会话有不同 ID。总开关默认开启；若此前统一暂停过，需要在设置中恢复。普通会话会在恢复时自动补建长期目标。已主动暂停的会话，即使自动恢复偏好保留，也不会被切号拉起。

先查看切号结果和会话卡片的「上次切号」：它会区分任务已提交、总开关关闭、未标记目标、无可续跑目标及回调失败。任务已提交后，继续查看任务日志中每个目标的投递结果。若页面提示后台仍在运行旧代码，先处理正在投递的任务，再从托盘退出并重新打开 Switcher；前台调试服务在原终端按 `Ctrl+C` 停止。刷新页面不能加载后端修复。

### 提示 Selected model is at capacity

这是模型繁忙错误（`server_overloaded`）。开启该会话的「切号自动恢复」及设置中的「自动恢复总开关」后，Switcher 会保留当前账号和模型，固定每 10 秒重试，连续失败也不延长间隔。单次或持续模式沿用原设置；暂停、完成、归档、正在运行或已有排队消息时跳过。无需打开管理页或开启自动切号，也不会因为这个错误消耗重置券。

续跑队列中的来源为「模型繁忙重试」；`/api/goals` 的 `capacity_recovery` 可查看各会话的重试时间、次数及已提交任务。重启 Switcher 保留等待时间，同一失败回合不会重复投递。服务器持续繁忙时可继续等待，或在 Codex 内手动调整模型后继续。

## 手机验证与接码

### 返回 `sms_not_configured`

在设置面板选择 `grizzly`、`smsbower`、`l` 或 `h`，并填写对应平台的连接信息。变量名称和默认值见[配置参考](reference.md)。

### 验证码改由 WhatsApp 发送

短信接码平台无法接收此类验证码。驱动检测到 WhatsApp 提示后会结束该次尝试并请求释放号码；连续拒绝可能返回 `sms_number_rejected`。查看登录事件，按账号验证页面实际提供的方式完成验证。

### 余额或取号测试失败，号码未立即释放

查看接码卡片的事件日志，核对平台地址、密钥、余额和号码状态。平台可能限制号码取消时间；服务会在允许后重试释放，实际退款结果以平台响应为准。

## 浏览器扩展

### 已安装但无法打开侧边栏

在 `chrome://extensions` 确认扩展已启用，再固定工具栏图标并点击。清单声明最低 Chrome 版本为 `114`，浏览器需支持 `chrome.sidePanel`。安装流程见[扩展说明](../extension/README.md)。

### 扩展无法连接服务，或徽章更新延迟

扩展固定连接 `http://127.0.0.1:8787`。若修改了服务端地址或端口，需恢复默认值，或同步调整扩展配置与权限后重新加载。

后台徽章按一分钟周期轮询，浏览器调度也可能造成延迟；侧边栏点击「刷新」可主动更新。徽章为 `?` 时，查看悬停提示和当前账号额度接口的错误。

### 修改扩展代码后未生效，或安装检测结果异常

在 `chrome://extensions` 点击扩展的重新加载按钮，再重新打开侧边栏。移动仓库目录后应从新路径重新加载；未打包扩展的标识与目录路径有关。

安装卡片提供目录及扩展页地址的复制功能，后续加载步骤需在浏览器内完成。检测结果与浏览器实际状态不一致时，以扩展管理页为准。

## 本地数据与托盘

### 复制数据目录后无法解密

Windows DPAPI 密文绑定原 Windows 用户，不能通过复制目录完成跨用户或跨机器迁移。请在目标环境重新导入账号并完成登录。

### 找不到托盘图标

检查任务栏的隐藏图标区域。重复打开 Switcher 会复用已有服务并打开管理页；需要结束后台服务时使用托盘菜单的「退出 Switcher」。
